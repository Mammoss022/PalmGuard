# PalmGuard AI — Training Pipeline

MobileNetV2 transfer-learning pipeline that classifies an oil palm leaf photo
into one of 3 classes: `Brown_Spot`, `Healthy`, `White_Scale`
(matches the DB's `disease_classes.code` case-insensitively — see
`docs/AI_MODEL.md#classes` for the exact mapping). No `Non_Palm` class yet —
see [Status](#status).
Full spec: [`docs/AI_MODEL.md`](../docs/AI_MODEL.md).

## Status

A real trained model is deployed: `models/mobilenetv2-v1.2.keras`, trained
externally on Google Colab (not via this repo's own `src/train.py` run —
`data/raw/<CLASS_NAME>/` is still empty here) on the 3 real disease classes
only, then wrapped with a `Rescaling(1/255)` input layer to match this repo's
"caller passes raw [0, 255] pixels" contract (see `src/model.py`) — the Colab
notebook itself trained on `ImageDataGenerator(rescale=1./255)` input, not
`preprocess_input`'s `[-1, 1]` scaling. Test-set evaluation (417 images):
98.6% accuracy — see `models/evaluation-v1.2.json` /
`models/classification_report-v1.2.txt` / `models/confusion_matrix-v1.2.png`.
Earlier Colab runs (`v1.0`, `v1.1`) are kept under `models/` but no longer
referenced by `backend/.env`. It has no `Non_Palm` rejection class, so an out-of-distribution photo relies
on `MIN_CONFIDENCE_THRESHOLD` (config.py) rather than an explicit trained
answer — see `src/predict.py`. Retraining with this repo's own pipeline (once
`data/raw/<CLASS_NAME>/` has real photos, optionally adding a 4th `Non_Palm`
class) is still open — everything under `src/` besides `predict.py` has only
been verified against synthetic/fake data so far.

## Layout

```
ai/
├── config.py           # shared constants (classes, image size, hyperparameters)
├── data/
│   ├── raw/<CLASS_NAME>/        # put source photos here, named <tree_id>_<seq>.jpg
│   └── splits/{train,val,test}/ # generated by src/dataset.py::split_dataset
├── models/              # exported .keras models + evaluation/history JSON land here
├── notebooks/
│   └── training.ipynb   # Colab-friendly run of the full pipeline below
├── src/
│   ├── data_cleaning.py # QA checklist: corrupt files, duplicates, blur, class balance
│   ├── dataset.py       # group-aware (by source tree) train/val/test split + tf.data pipelines
│   ├── augmentation.py  # train-only: flip, rotation, zoom, translation, brightness, contrast
│   ├── preprocessing.py # resize/RGB/validate — same contract at train and inference time
│   ├── model.py         # MobileNetV2 (frozen) + GAP -> Dense(128, relu) -> Dropout -> Dense(3, softmax)
│   ├── train.py         # Phase 1 (frozen base) then Phase 2 (fine-tune top layers)
│   ├── metrics.py        # Accuracy/Precision/Recall/F1/ROC AUC/confusion matrix (pure NumPy)
│   ├── evaluate.py       # runs a model over a dataset -> metrics.build_report()
│   ├── predict.py        # single-image inference (what a deployed model would use)
│   └── export_model.py   # saves the trained model under models/
└── requirements.txt
```

## Usage

```bash
cd ai
python -m venv .venv && .venv/Scripts/activate   # or source .venv/bin/activate
pip install -r requirements.txt

# 1. Put photos under data/raw/<CLASS_NAME>/, named <tree_id>_<seq>.jpg
#    (see docs/AI_MODEL.md#dataset — grouping by tree matters, avoids leakage)

# 2. QA the dataset before training
python -m src.data_cleaning

# 3. Train (splits the dataset, runs both training phases, evaluates, exports)
python src/train.py
```

Or run [`notebooks/training.ipynb`](notebooks/training.ipynb) on Google Colab
for GPU training.

## Where this fits with the rest of the app

The Backend can point at either inference backend via `backend/.env`:

```
AI_BACKEND=mobilenet
MOBILENET_MODEL_PATH=/absolute/path/to/ai/models/mobilenetv2-v1.2.keras
```

`backend/app/services/inference.py` dispatches based on that flag;
`mobilenet_inference.py` loads and runs the model by importing
`ai/src/predict.py` and `ai/config.py` directly (no logic duplicated between
the two packages). No endpoint code needs to change either way. The Gemini
path (`AI_BACKEND=gemini`, `app/services/ai_inference.py`) is still the only
one with a `Non_Palm` rejection class.
