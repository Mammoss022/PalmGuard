# แบบประเมินความพึงพอใจ

## การบันทึกข้อมูล

คำตอบบันทึกในตาราง `satisfaction_surveys` ผูกกับ `users.id` ผ่าน `user_id`
เก็บคะแนนความพึงพอใจ ความง่ายในการใช้งาน ความแม่นยำตามความคิดเห็นผู้ใช้
การแนะนำระบบ ความคิดเห็นเพิ่มเติม และเวลาส่ง (`created_at`, API ส่งเป็น UTC)

การตั้งค่าปัจจุบัน `backend/.env` ใช้ `sqlite:///./palmguard.db`
เมื่อเปิด backend จากโฟลเดอร์ `backend` ข้อมูลจึงอยู่ที่ `D:/PalmGuard/backend/palmguard.db`
หากเปลี่ยน `DATABASE_URL` ข้อมูลจะบันทึกในฐานข้อมูลที่ตั้งไว้แทน

## ผู้ใช้

- หลังมีการวินิจฉัยสำเร็จ หน้าหลัก/หน้าผลวินิจฉัยจะแสดงหน้าต่างหลัง 8 วินาที
- ตรวจ `GET /api/v1/surveys/me` จากฐานข้อมูลก่อนแสดง และตรวจอีกครั้งก่อนเปิด
- ปิดหรือเลือกทำภายหลังจะไม่ชวนซ้ำใน session ของแท็บนั้น แต่ยังเข้าหน้า `/survey` ได้
- เมื่อส่งแล้วจะไม่แสดงหน้าต่างอีกแม้เปลี่ยนเครื่อง หน้า `/survey` แสดงคำตอบเดิมอย่างเดียว
- ส่งผ่าน `POST /api/v1/surveys` ได้หนึ่งครั้งต่อบัญชี ส่งซ้ำตอบ `409`
- unique index จาก migration `0004_one_survey_per_user` ป้องกันการส่งซ้ำพร้อมกัน
- เก็บคำตอบเดิมทั้งหมด ถ้าฐานข้อมูลอื่นมีคำตอบซ้ำอยู่ก่อน migration จะหยุดโดยไม่ลบคำตอบ

## แอดมิน

- `/admin` แสดงสถานะแบบประเมินของแต่ละบัญชี
- `/admin/users/<id>` แสดงคำตอบและประวัติของผู้ใช้ อ่านได้อย่างเดียว
- `/admin/surveys` มีกราฟคะแนน 1–5 ของสามข้อ กราฟแนะนำ/ไม่แนะนำ
  จำนวนผู้ตอบ ค่าเฉลี่ย และความคิดเห็นรายคน พร้อมแบ่งหน้า
- กราฟคำนวณจากคำตอบทั้งหมด ไม่ใช่เฉพาะหน้าในรายการคำตอบ
- `GET /api/v1/admin/surveys` รองรับ `user_id`, `page`, `page_size`
- `GET /api/v1/admin/surveys/summary` ส่งสรุปทั้งหมด
- ทุก admin endpoint บังคับสิทธิ์ admin ที่ backend ไม่มี endpoint เพิ่ม/แก้ไข/ลบคำตอบใน admin
- คะแนนความแม่นยำเป็นความคิดเห็นผู้ใช้ ไม่ใช่ค่า accuracy จากชุดทดสอบโมเดล

## ตรวจสอบ

จาก `backend`: `.venv/Scripts/python.exe -m unittest discover -s tests -v`
ทดสอบสถานะก่อน/หลังส่ง การส่งซ้ำ สิทธิ์แอดมิน การอ่านคำตอบรายคน
กราฟจากข้อมูลทั้งหมด และ unique index โดยใช้ SQLite แยกจากฐานข้อมูลจริง
